# Act 2 Rework Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Hired employees build parts at their desks, office perks and decor are placed in a spacious decorate zone, and the Act 2 deploy battle becomes Squad Galaga (wingmen, client-specific enemies, boss bullet volleys).

**Architecture:** New pure modules in `ReplicatedStorage/Shared` hold the rules and are tested in Lune: `Workforce` (employee build timing), `Decor` (placement validation and perk bonuses), and extensions to `BattleState` (ship position, wingmen, new enemies, bullets). Server services apply them: `EmployeeService` gets a work loop, `DecorService` is new, `BattleService` passes Act 2 options. Code-built decor models live in a new `ReplicatedStorage/World/DecorModels` so the server and the client ghost preview build identical models.

**Tech Stack:** Roblox Luau `--!strict`, Rojo 7.7, Lune 0.11 tests (`lune run tests/run.luau`), luau-lsp.

**Spec:** `docs/superpowers/specs/2026-10-30-act2-rework-employees-squad-decor-design.md`

## Global Constraints

- `--!strict`; `game:GetService` at the top; `task` library only; no `pairs`/`ipairs`; PascalCase modules, camelCase locals, LOUD_SNAKE_CASE constants (`CLAUDE.md`).
- Pure modules in `ReplicatedStorage/Shared`: no requires, no Roblox APIs; data comes in as parameters.
- Server authority: every part grant, purchase, placement, move, sell, ship move and kill is validated on the server.
- Cash only comes from a deploy battle the player finishes (spec §1).
- English, generic setting, cyberpunk/vaporwave look; code-built art only; sounds from the existing licensed set.
- Verification for every task: `lune run tests/run.luau` passes; `rojo sourcemap -o sourcemap.json && luau-lsp analyze --sourcemap=sourcemap.json --definitions=types/globalTypes.d.luau src` is clean; `rojo build -o game.rbxl` succeeds.
- Numbers pinned by the spec: employee part every 25 s at grade B; perks coffee +20% speed $400, lounge 15% grade A $650, arcade +10% speed $900, one of each; units 64×64; decorate zone 28×24 studs, 2×2-stud cells (14×12 cells); sell refund 50%; 200 placed items max; Database wingman shield recharge 8 s.

## Review Focus

1. **Employees overshoot the recipe.** If a player run and an employee part land in the same tick, the job must not end up with more parts than it needs (upgrade-don't-add still holds). *Pinned: Task 1 test `employees stop once the need is met`.*
2. **Decor that blocks or escapes the zone.** A crafted `DecorPlace` with negative cells, a fractional cell, a 45° rotation or a footprint hanging off the edge must be rejected. *Pinned: Task 3 tests.*
3. **Selling a perk mid-work.** Perk bonuses must drop the moment the perk is sold, with no leftover speed. *Pinned: Task 3 `perks follow what is placed`.*
4. **Speed-hacked ship.** A client sending ship positions that jump across the field must be clamped, so it can't dodge bullets by teleporting. *Pinned: Task 6 `ship moves are clamped to max speed`.*
5. **Split shards and kill claims.** A kill claim for a shard that hasn't spawned yet, or with a wingman weapon the player doesn't have, must be rejected. *Pinned: Task 7 `claims need the weapon and a live bug`.*

**Interfaces:**
- Produces:

  - **Crash:** killing a Crash appends two `Shard` bugs at its current position (`BugPosition` at `now`), at x ± `ShardSpread`. Each shard has `SpawnAt = now`, `EntryTime = 0.2`, `DiveAt = now + ShardDiveDelay`, `ReachAt = DiveAt + ShardDiveTime`, `Hp = 1`, and a random `DiveX` from `b.Rng`.

  - **Bullets:** with `BossVolleys`, `b.Bullets: { Bullet }` is generated in `New`. `Bullet = { Id, FiredAt, OriginX, OriginY, DirX, DirY, State: "Live" | "Hit" | "Gone" }`.

    - Each volley has `VolleySize` bullets fanned evenly across `VolleySpreadDegrees`, centered straight down, from the boss position at `FiredAt`, at `BulletSpeed`.

      - If it was fired after the boss died (`b.BossDiedAt`), it becomes `Gone`.
      - If `|x − ShipXAt(tCross)| <= HitRadius`, it becomes `Hit` and applies the damage order.
      - Otherwise it becomes `Gone`.
  - `BattleSnapshot` gains `BugCount: number`, `SlowUntil: number`, `BossDiedAt: number?`, `WingShieldReadyAt: number`.
